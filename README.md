# Token Optimized Software Harness (tosh)

## Concept
An AI dev harness which prioritizes token conservation and speed. Token usage is a major issue for all organizations as 
they burn through money. Higher token counts not only cost more, they also take longer to run. Token conservation 
results in faster runs and cost optimization.

`tosh` is a CLI based agentic software development harness which prioritizes local processing for token optimization, 
resulting in increased speed of development harness and reduced token cost.

---

## Foundation
What makes this concept token efficient is the use of parseable project and development documentation. In order to
achieve this some level of structure must be defined to ground the AI quickly and easily. LLMs have long shown positive
results when processing `XML` tagging.

The foundation that underlies all development pipeline documents is `XHTML`. `XHTML` is a highly effective
polyglot format in this use case as it can be used for rich UI rendering via a browser or can be parsed and traversed 
at highly efficient speeds and delivering only the portions of content relevant to the task and nothing more. This
process will drastically reduce token usage as full document loads are no longer needed.

`tosh` working in concert with a Code Graph tool can take things a step further.

## Document Domain Breakdown

### Work Item Documents
Work item documents drive the technical development phase from story activation through pull request. These
documents are responsible for detailing requirements, acceptance criteria, technical design, implementation plans, 
phases, review, validation, summaries, LLM conversations, etc. 

### Wiki Documents (project)
The wiki documents hold all of team's general project information. These include artifacts like a project overview, 
project styles, coding guidelines, risk registry, design decisions, project setup guide, etc.

### Code Documents
Code documents are those generated by the code's automatic documentation generation engine. Also knows as API 
documentation it specifies you packages/modules, classes, interfaces, etc.

### OpenAPI Documents
OpenAPI specification are important clients and LLMs. This domain of documents contain both the service app being
built(if it exposes endpoints) and the services the application call as a client.

## Visualization
This framework provides a base page in which a developer can see documents from all domains in a single pane.

## Components

### CLI
The CLI is the distributed application binary. The CLI initializes `tosh` and is used to launch the other components
delivered within the CLI. It also can be used to perform any action `tosh` has available. The CLI is responsible 
for reading and writing project documentation via a defined XHTML schema to define a parsable XML document on every
run. The CLI allows querying documents and pulling out specific subsets of data within the documentation. The CLI
also provides easy real-time management of checklists. 

### MCP
The MCP server is bundled in the CLI and allows for a cleaner and less chatty usage of the CLI by the agentic LLM
development tool.

### RestAPI
The REST API is bundled in the CLI. When this RestAPI server is running it can be interfaced from any 3rd party
application which has integrated with the REST API. These could allow for a rich UI like React, Angular, Vue, etc.

### UI
The UI templates are bundled in the CLI to build local files. In the initial phases the UI will be completely static
and be maintained by the CLI.

---

## Data Storage

### Local Data Storage
All the documentation needed to implement application features and fixing bugs are stored locally. Local storage
minimizes cloud traffic and latency in a process where time matters. 

### Repo Storage
When documentation has been created or updated it gets added to source control allowing for cross team document
synchronization with a traceable history and effective merging. This also reduces time across the team as each
team member doesn't need to generate their only local copy of the code. 

---

## Partner Project
At the beginning this harness will utilize `CodeGraph` for token optimization when working with source code files.

In time `tosh` may gain it's own knowledge graph for code making this a more all-in-one solution.

---

## Not a Project Management System
This is not a project management systems but instead allows for the integration with project management systems. The
CLI will allow for the expansion of capabilities through add-on modules. In the case of project management a module
form Jira, Linear, ADO, or other could be created. The team using `tosh` could download the Jira module if their team
uses Jira for project management.
